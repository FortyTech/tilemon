## Done when

The collector reads its `namePattern` override from `~/.tilemon/config.json`, the path the setup guide
(`skills/tilemon/references/setup.md`) and the comments in `collector.mjs` both give, and a user who
follows the docs gets their pattern applied. A `config.json` in the boards folder no longer shows up as
a phantom board called `config`. An existing `~/.claude/config.json` keeps working (read as a fallback)
so the live install doesn't silently lose its routing.

## Why

`runCollector` and `collect --dry-run` call `loadConfig(CC_DIR)`, and `CC_DIR` is `~/.claude`, so the
code reads `~/.claude/config.json`. Everything written for humans says `~/.tilemon/config.json`.
On 2026-08-27 William's sessions all landed in `inbox` because his `### - PROJECT - description` names
didn't fit the default pattern; the override was written to the documented path first and had no
effect, and only worked once moved into `~/.claude`, a folder that belongs to Claude Code, not TileMon.

The documented path is also unsafe as things stand: the local server treats every `*.json` in
`~/.tilemon` as a board, so following the docs adds a board named `config` to the board list.

## Notes

- Fix the read path, keep `~/.claude/config.json` as a fallback, and make `listSlugs` in `server.mjs`
  skip `config.json`.
- The hosted app lists boards from the database, so only the local server has the phantom-board problem.
