## Done when

A tile for a session with an open PR shows a clickable **`PR #n ↗`** chip that opens the PR on
GitHub in a new tab; the chip turns **red** when that PR's CI is failing; a session with no open PR
shows no chip. Works on both the local `npx tilemon` board and hosted tilemon.com. Clicking a chip
navigates — it does not drag/resize/drill the tile.

## Status — BUILT (tilemon 0.21.0), rollout pending

The data already existed: `countSignals` reads each session's `job.children` PRs and their state
from `gh-pr-status-cache.json` to compute the open-PR signal. This surfaces it as a link rather than
just a count — no new source.

- **collector.mjs** — `countSignals` now also returns `openPRs`; new `prLinks(openPRs, prStatus)`
  export maps each OPEN PR to `{ href, number, ciFailed }` (number parsed from `…/pull/<n>`). Each
  tile gets a `prs` array **only when non-empty** (omitted otherwise → lean nodes, no write-churn).
- **engine.js + tilemon-cloud board-source.ts** — `prs` carried through both `resolveBoard`
  implementations into the render tree (same one-line pattern as `signals`).
- **board.js** — `prChips(node)` renders one `<a class="pr">PR #n ↗</a>` per open PR (`.pr.bad` red
  variant when `ciFailed`); dark-pill CSS so it reads on any signal colour; `onDown` + `dblclick`
  guard `.pr` so a chip click navigates (target=_blank, rel=noopener) instead of dragging/drilling.
  href/number/title are escaped; number is digits-only from the URL.
- **tilemon-cloud schema.ts** — `BoardNode.prs?`.
- **Tests** — collector: `prLinks` (open→chip, merged→none, failing-CI flag, non-PR href→null number),
  projection attaches `prs` only when a PR is open. board: render asserts the chip anchor + `.bad` +
  absence. Full suite green (board + engine + collector 45 + server + reconcile).

## Caveat
Only **collector session tiles** carry a PR href (from `job.children`). Standalone PR *pins* a human
placed (e.g. the `PR #28` pin moved onto forty-tech) are just named — no href — so they won't
linkify unless a URL is added to them. In practice the live session tile is the one to click.

## Why
The open-PR signal already turns a tile amber/red, but "there's a PR" then makes you go find it. The
board's job is to direct attention to the exact thing that needs you — one click to the PR closes
that gap. Reinforces the signal-count model (red chip = the failing-CI signal) rather than adding a
parallel concept.
