## Done when
No write can land an unclassified tile on the **root** of `home` (or any board the human uses as
structure). Anything with no valid destination goes to the existing **`inbox`** board instead:

- **The immediate fix (small):** board-less / unrouted writes on the legacy `POST /api/status`
  path — hosted route + local `server.mjs` + the `tilemon flag` CLI default — default to **`inbox`**,
  not `home`. Today they default to `home`, so any stray `flag` (a session running the retired path,
  a manual call, another machine) pins an un-clearable tile on the human's home root. `inbox` already
  exists (the collector routes unroutable sessions there); this just points the last writer that
  still targets `home` at it too. Verify: a `flag`/`/api/status` with no board no longer appears on
  `home`; it appears on `inbox`.
- **The fuller exploration (this ticket's original scope):** a per-board *uncategorised* container
  that receives no-home tiles, hidden when empty (generalises into TIL-004), born small, with a
  one-gesture way out (needs the Move UI, roadmap E). Engine-level so hosted inherits it.

## Why
Tiles keep appearing at the top level of a board. That is the *designed*
behaviour, not a bug — a node with no bucket is created as a child of the root
(upsert creates missing path nodes; `reconcile` parks genuinely-unmatched tiles
on the home board's root by design, with a caller alert). But the effect is
wrong: the top level is the most valuable real estate on the board, and
anything unclassified lands there by default, competing on equal footing with
the buckets the human deliberately laid out.

Attention is the product. Unsorted noise should not be the thing sitting at the
top of the frame.

**Recurred 2026-08-13.** After the passive-collector cutover (which fixed *collector* accumulation via
the `origin:'session'` ownership model), `home` filled again with 7 loose `origin=none` pins (FFF +
diarization work). Root cause confirmed: the retired self-report path (`/api/status`, defaults to
`home`) is still reachable and still deposits un-clearable pins on the root — the passive model can't
sweep them (no `origin`). This is the immediate-fix half above: close the last writer that targets
`home` by default. The skill is already retired (agents are told not to flag) and nothing in the
workspace calls it, so the remaining writes are ad-hoc — routing them to `inbox` neutralises them
regardless of source.

## Notes
The idea to explore: a single **uncategorised** container per board that
receives anything with no home, instead of the root itself.

- Hidden when empty — so a tidy board never shows it at all. (That generalises
  into TIL-004, which is the same toggle applied to every container.)
- Born small, and stays small: it should read as an inbox, not a bucket with
  standing.
- Filing out of it must be one gesture — `/api/move` exists; the Move UI
  (roadmap item E) is the missing half. Without an easy way *out*, an inbox is
  just a second place for things to rot.

Open questions:

- Does this actually reduce noise, or just move it one tile down and add a
  layer of indirection? Test the honest version: does an unclassified tile
  still glow, and if so, has anything really changed? (If it glows the same,
  the win is layout, not attention.)
- Should `reconcile`'s park-on-root behaviour and `/api/status` upsert both
  target it, or only the reconciler's guesses? Arguably an agent that names an
  explicit new path *has* said where it goes.
- Per-board, or one workspace-level inbox? Per-board is more consistent with
  the model; one global inbox is more likely to actually get triaged.
- Interaction with heat rollup: an uncategorised container aggregates the heat
  of everything in it, so a busy inbox becomes a large glowing tile — possibly
  the right pressure to file things, possibly just noise with a name.
- Engine-level, so hosted (tilemon-cloud) inherits it via the npm package
  rather than getting a second implementation.
