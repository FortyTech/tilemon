## Done when

`tilemon flag --project <p> --path <x> --status <s>` returns success against the
local daemon, and the tile visibly changes on the board.

## Why

Every agent write is currently failing. `POST /api/status` returns
`400 {"error":"bad or missing board slug"}`, so `tilemon flag` reports
"write did NOT land" and the board silently freezes at whatever it last said.

That is worse than an outage you can see. The board is the attention surface —
when writes fail quietly, it keeps confidently displaying stale claims. On
2026-07-30 it was still showing "26 modified + 2 untracked files awaiting
commit" and "Swift-Join deprecation — awaiting confirmation" hours after both
were finished and merged.

The cause is a contract drift: the daemon went multi-board (`GET /api/boards`
lists 31 slugs, one per repo) and now requires a `board` slug on writes. The CLI
was never updated — it sends `project`, which the server ignores.

## Done when — verified by

    # fails today
    curl -X POST localhost:4000/api/status -H 'content-type: application/json' \
      -d '{"project":"forty-workspace","path":"git","status":"done"}'
    # -> 400 bad or missing board slug

    # succeeds today
    curl -X POST localhost:4000/api/status -H 'content-type: application/json' \
      -d '{"board":"forty-workspace","path":"git","status":"done"}'
    # -> 200 {"ok":true}

## Notes

- `board` goes in the **body**. A `?board=` query param still 400s, and
  `/api/boards/<slug>/status` is 404 — so the body field is the only shape the
  server accepts.
- Decide how `--project` maps to a slug: they matched for `forty-workspace`, but
  the board list uses `tilemon-app`, `home`, `research` and `tutorial`, which
  are not repo directory names. A wrong-but-valid slug writes to the wrong board
  silently, so this mapping is the actual risk, not the field rename.
- Reads are unaffected — `GET /api/state?glowing=1` works, which is why the
  start hook still shows the board correctly.
